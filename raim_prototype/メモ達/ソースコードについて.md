## 今、何が動いているか

「**LLMに繋いでないけど、UIは完成しているチャットアプリ**」が動く状態。

### 動作確認できること

1. テキスト入力欄に文字を入れて送信ボタン or Enterキー
2. ユーザーメッセージが右側に青色で表示される
3. 「考え中...」が約1秒表示される
4. AIっぽいメッセージが左側にグレーで表示される（固定の応答）
5. 感情ラベル（「感情: happy」）も表示される

### まだできていないこと

- 本物のLLM接続（Ollama や Bedrock）→ 次フェーズ
- Unity との連携 → 次フェーズ
- 音声入力・音声出力 → 後のフェーズ
- 画像入力 → 後のフェーズ
- 認証や履歴保存 → 本番化フェーズ

## 全体の流れ（ユーザーがメッセージを送信したとき）

```
ユーザーが「おはよう」と入力して送信ボタンを押す
   ↓
[ChatInput]          入力欄が値を取り出して、ChatProviderに依頼
   ↓
[ChatProvider]       履歴に「ユーザーが言った」と追加、UIに「変わったよ」と通知
   ↓
[MessageList]        画面に新しいメッセージを描画（ユーザー側）
   ↓
[ChatProvider]       「考え中」フラグをON、UIに通知
   ↓
[MessageList]        「考え中...」を表示
   ↓
[ChatProvider]       MockLLMServiceを呼んで応答を待つ（1秒）
   ↓
[MockLLMService]     固定の応答を返す（"〇〇って言ったね！"、emotion: happy）
   ↓
[ChatProvider]       履歴にAI応答を追加、「考え中」フラグをOFF、通知
   ↓
[MessageList]        画面にAI応答を描画（左側、感情付き）
```

これがコードを書いて作った全体の流れ。

## ファイル詳細

### `main.dart` — アプリの起点

アプリ起動時に最初に動くファイル。3つのことをしている：

1. アプリ全体のデザインテーマを設定
2. ChatProvider（状態管理）をアプリ全体に提供
3. 最初に表示する画面（ChatScreen）を指定

ここに `MockLLMService()` を渡しているのが重要。
将来 Ollama や Bedrock に切り替えるとき、**ここの1行だけ変えれば済む**ように設計されている。

```dart
ChatProvider(MockLLMService())  // ← この MockLLMService の部分を変える
```

### `models/message.dart` — チャットメッセージの形

「チャットの1件のメッセージは、こういう情報を持つ」という設計図。

- text: 内容
- role: 誰が言ったか（user / assistant）
- timestamp: いつ言ったか
- emotion: どんな感情か（AIの応答のみ）
- intensity: 感情の強さ（AIの応答のみ）

### `models/llm_response.dart` — LLM応答の形

LLMから返ってくる生データの形。

- text: 応答テキスト
- emotion: 感情
- intensity: 強度

`fromJson` というメソッドがあって、JSON文字列からこの形に変換できる。
（詳しくは `Dart_factoryコンストラクタの解説.md` を参照）

### `services/llm_service.dart` — LLM呼び出し

ここが**プロトタイプ→本番の切り替えポイント**。

2つのクラスがある：

**`LLMService`（抽象クラス・インターフェース）**
- 「LLMサービスはこういう機能を持つ」と決めるだけ
- 中身は書かない

**`MockLLMService`（実装クラス）**
- 「LLMServiceに従って、こう動く」と中身を書く
- プロトタイプ用に、本物のLLMに繋がず固定応答を返す
- 1秒待ってから「〇〇って言ったね！」と感情付きで返す

将来追加するクラス：

**`OllamaService`（後で追加）**
- ローカルPCのOllamaに HTTP リクエストする実装

**`BedrockService`（本番で追加）**
- AWS Lambdaを経由してBedrockを叩く実装

どれも `LLMService` というインターフェースに従うので、**ChatProviderの中身を変えずに切り替えられる**。

### `providers/chat_provider.dart` — チャットの頭脳

ここがアプリの中で**一番重要**な部分。

主な仕事：

- チャット履歴を保持する
- ローディング状態を管理する（応答待ち中かどうか）
- ユーザー入力を受けて、LLMサービスに渡す
- LLM応答を受けて、履歴に追加する
- 変化があったらUIに通知する

`ChangeNotifier` というFlutter標準の仕組みを使って、状態が変わるたびに `notifyListeners()` を呼ぶ。これでUIが自動で更新される。

### `screens/chat_screen.dart` — チャット画面

画面のレイアウト。

- 上部: タイトルバー（AppBar）
- 中央: メッセージ一覧（MessageList）— 残ったスペース全部使う
- 下部: 入力欄（ChatInput）

シンプルに `Column`（縦並び）で組んでいるだけ。

### `widgets/message_list.dart` — メッセージ一覧

ChatProviderの履歴を受け取って、スクロール可能なリストとして表示。
ローディング中は「考え中...」も表示。

`Consumer<ChatProvider>` を使って、ChatProviderの変化を購読している。
ChatProviderが `notifyListeners()` を呼ぶたびに、このリストが再描画される。

### `widgets/message_bubble.dart` — 1件のメッセージの見た目

1件のメッセージを「吹き出し」として表示。

- ユーザーのメッセージ: 右寄せ、青系の色
- AIのメッセージ: 左寄せ、グレー系の色
- 感情情報があれば下に小さく表示

### `widgets/chat_input.dart` — 入力欄

下部の入力欄＋送信ボタン。

- TextField でテキスト入力
- 送信ボタンか Enter キーで送信
- 送信時に ChatProvider に処理を依頼
- 送信後に入力欄をクリア

ここだけ `StatefulWidget` を使っている。理由は、入力中のテキストを管理する必要があるから。
（他のウィジェットは `StatelessWidget` で、自分では状態を持たない）

## 設計の重要ポイント

### 役割分担

各ファイルが「自分の仕事」だけをやる。

- データの形は models/
- 外との通信は services/
- 状態管理は providers/
- 画面構造は screens/
- 部品は widgets/

これにより、何かを変更したいときに「どこを触ればいいか」が明確になる。

### インターフェース化

`LLMService` という抽象クラスを作って、その実装として `MockLLMService` を用意している。
これにより、後で Ollama → Bedrock に切り替えるとき、**main.dart の1行だけ変えれば済む**。

これを**依存性注入**という。プロの現場でもよく使う設計手法。

### 状態管理の流れ

```
ユーザー操作 → ChatProvider → notifyListeners() → UI再描画
```

ChatProvider が状態の唯一の管理者で、UI は ChatProvider を購読しているだけ。
これにより、状態と表示が綺麗に分離されている。

## 次のステップ

プロトタイプの土台はこれで完成。次にやること（時系列順）：

### 短期（デスクトップに戻ったら）

1. **Ollama接続**: `services/llm_service.dart` に `OllamaService` 実装を追加
2. **動作確認**: `main.dart` の1行を `MockLLMService` から `OllamaService` に変える
3. **JSON応答の安定化**: システムプロンプトで `{text, emotion, intensity}` を確実に返させる

### 中期

4. **Unity接続**: WebSocket で感情パラメータを Unity に送る処理を services/ に追加
5. **Unity側**: 立ち絵切り替え、口パク、表情制御を実装
6. **STT**: sherpa-onnx を組み込んで音声入力対応

### 長期（本番化）

7. **Bedrock接続**: AWS Lambda 経由で Bedrock を叩く実装
8. **認証**: Cognito 連携
9. **履歴永続化**: DynamoDB 連携
10. **アプリパッケージング**: iOS, Android, Windows 向けビルド

## つまずいたら

### よくあるエラー

**`The method 'XXX' isn't defined for the type 'YYY'`**
→ メソッド名のタイポ、importしてないクラスを使っている等

**`Undefined name 'XXX'`**
→ import文が抜けている

**`Expected to find ';'`**
→ セミコロンが抜けている

**`Try removing the 'const' keyword`**
→ 動的な値を const にしている。const を外す。

### Hot Reload と Hot Restart

- **Hot Reload (`r`)**: 保存ボタンや `r` キーで即反映。普段はこれ。
- **Hot Restart (`R`)**: 状態をリセットして再起動。Provider周りで挙動がおかしいとき。
