## 動作の全体像

ユーザーが「FF14が好きなんだ」と入力したときの処理：

```
[ChatInput (widgets/)]  
   ↓ context.read<ChatProvider>().sendUserMessage("FF14が好きなんだ")
   ↓
[ChatProvider (providers/)]
   1. ユーザーメッセージを履歴に追加、UI 更新通知
   2. isLoading = true、「考え中...」表示
   3. 直近20件の履歴を切り出す
   4. _llmService.sendMessage(text, history: 履歴) を呼ぶ
   ↓
[OllamaService (services/)]
   1. システムプロンプト + 履歴 + 最新入力 を messages 配列に組み立て
   2. options（temperature, top_p）を付ける
   3. http://localhost:11434/api/chat に POST
   ↓
[Ollama / Gemma 3 12B IT]
   推論実行（1〜3秒）
   ↓
[OllamaService → ChatProvider]
   レスポンスを LLMResponse に変換して返す
   ↓
[ChatProvider]
   1. LLM 応答を履歴に追加
   2. UnityCommunicator.sendEmotion() → Unity に送信
   3. TTSService.speak() → VOICEVOX で読み上げ
   4. isLoading = false、UI 更新
   ↓
   ├→ [UnityCommunicator]
   │     Windows: WindowsUnityBridge → WebSocket → Unity
   │     Mobile:  EmbedUnityBridge → sendToUnity → Unity
   │       ↓
   │     [Unity RAiMCharacterController]
   │       emotion → Sprite 切替（立ち絵が変化）
   │
   ├→ [TTSService]
   │     VOICEVOX API (localhost:50021)
   │       audio_query → synthesis → WAVバイナリ
   │     audioplayers で再生 → 春日部つむぎが読み上げ
   │
   └→ [MessageList → MessageBubble]
        「FF14がお好きなんですね…」を左側に表示、感情ラベル付き
        [CharacterDisplay]
          emotion で立ち絵画像（Windows用フォールバック）が切替
```

## システムプロンプトの構造

`OllamaService` 内で、システムプロンプトを3パートに分割：

```
_commonProfile（共通プロフィール）
    + 性格パターン（A/B/C のいずれか）
    + _outputFormat（JSON出力指示）
```

### 共通プロフィール

性格に関わらず常に適用される、ライムの基本情報：
- 名前: ライム（表記: RAiM、"i"が小文字なのは"Ai"を込めている）
- 関係性: ユーザーの相棒・友達・先輩・雑談相手
- 共通の興味（ゲーム、アニメ、技術、音楽など）

### 性格パターン

3つから切り替え可能：

| パターン | 一人称 | 二人称 | 口調 | 特徴 |
|---|---|---|---|---|
| A: 知的相棒 | 私 | あなた | 丁寧・敬語ベース | 落ち着いた秘書っぽさ |
| B: クール先輩 | 私 | きみ・名前 | 砕けた口調 | 親しみやすい同年代感 |
| C: ギャップ萌え | 私 | あなた | 普段クール | 好きな話題で素が出る |

### 出力形式

JSON 形式で `text + emotion + intensity` を返すよう指示。
emotion は 6種類（happy/sad/angry/surprised/neutral/caring）から選択。

`OllamaService.sendMessage` 内で、3パターンのプリセットをコメントアウト切り替え：

| パターン | temperature | top_p | 特徴 |

| 1: 控えめ | 0.3 | 0.9 | 決定的、安定、JSONも崩れにくい |
| 2: バランス | 0.8 | 0.9 | 自然で個性的、推奨 |
| 3: クリエイティブ | 1.1 | 0.95 | 予測不能、生き生き、JSON崩れリスク |

## VOICEVOX 音声合成

### 構成

VOICEVOX エンジンを localhost:50021 で起動 → Flutter から HTTP API を叩く流れ。

```
[Flutter ChatProvider]
   ↓ TTSService.speak("おはよう！")
[TTSService]
   1. POST /audio_query?text=おはよう&speaker=8
      → 音声合成クエリJSON
   2. POST /synthesis?speaker=8 + クエリJSON
      → WAVバイナリ
   3. audioplayers で BytesSource として再生
   ↓
[ユーザー] 春日部つむぎの声で聞こえる
```

### 設定

- 話者ID: 8（春日部つむぎノーマル）
- レスポンス時間: 1〜2秒程度
- 完全無料、ローカル動作

### Windows特有の対応

`windows/CMakeLists.txt` の `APPLY_STANDARD_SETTINGS` 関数を修正：

- `/utf-8` オプションで文字コード強制
- `_SILENCE_EXPERIMENTAL_COROUTINE_DEPRECATION_WARNINGS` を定義して警告抑制

これらは Flutter Windows ビルドで audioplayers パッケージの C++ 互換性問題を回避するため。

## プラットフォーム別の Unity 通信

抽象化レイヤー `UnityCommunicator` で実装を切替：

### Windows: WebSocket 方式

```
[Flutter (サーバー)] ──ws://localhost:8765── [Unity (クライアント)]
WindowsUnityBridge                          RAiMCharacterController
shelf_web_socket                            NativeWebSocket
```

- Flutter 側が WebSocket サーバーを起動
- Unity が起動すると自動接続
- emotion 変化時に Flutter から Unity にブロードキャスト

### iOS/Android: sendToUnity 方式

```
[Flutter (アプリ)] ─── sendToUnity ── [Unity (埋め込み)]
EmbedUnityBridge                       RAiMCharacterController
flutter_embed_unity                    ReceiveEmotion メソッド
```

- flutter_embed_unity で Unity を Flutter アプリ内に埋め込み
- `sendToUnity("character", "ReceiveEmotion", "happy")` で Unity の C# メソッドを直接呼ぶ
- WebSocket 不要、プロセス内通信

### main.dart で自動切替

```dart
UnityCommunicator _createUnityBridge() {
  if (Platform.isAndroid || Platform.isIOS) {
    return EmbedUnityBridge();
  }
  return WindowsUnityBridge();
}
```

ChatProvider は具体実装を知らない。これにより**Flutter コードの大半が全プラットフォームで共通**。

## 環境セットアップ手順（再現用）

### 1. Ollama インストール

1. https://ollama.com からインストーラ DL
2. 環境変数 `OLLAMA_HOST=0.0.0.0:11434` を設定（Tailscale経由で叩くため）
3. Windows ファイアウォール: ポート 11434 (TCP) 受信許可
4. `ollama pull gemma3:12b`（約8GB）

### 2. Tailscale セットアップ（学校から叩く場合）

1. https://tailscale.com でアカウント作成
2. デスクトップにインストール、ログイン
3. 「Run unattended」設定（再起動後も自動接続）
4. Tailscale IP（100.x.x.x）メモ
5. 学校ノートPCにも同じアカウントでインストール

### 3. Visual Studio 2022（Flutter Windows ビルド用）

1. https://visualstudio.microsoft.com/ja/downloads/ から Visual Studio Community 2022
2. ワークロード「C++によるデスクトップ開発」選択
3. インストール完了後 `flutter doctor` で確認

### 4. Flutter プロジェクト起動

```bash
cd raim_prototype
flutter pub get
flutter run -d windows
```

### 5. Unity（立ち絵切り替え用）

1. Unity 2022 LTS で `unity/raim_unity` を開く
2. NativeWebSocket は `Packages/manifest.json` に Git URL 経由で登録済み
3. Editor 起動 → Play モード（WebSocket クライアントとして接続）

### 6. VOICEVOX（音声合成用）

1. https://voicevox.hiroshiba.jp/ から VOICEVOX ダウンロード
2. インストール、起動するとタスクトレイ常駐、localhost:50021 で HTTP サーバー
3. Flutter 側は自動で接続して使う

### 7. Visual Studio 開発者モード有効化

`flutter_embed_unity` などのプラグインのシンボリックリンク機能のため：

PowerShell: `start ms-settings:developers` → 開発者モード ON

## トラブルシューティング

### Ollama に繋がらない

- タスクトレイにラマアイコンあるか確認
- 環境変数 `OLLAMA_HOST` が反映されてるか: `echo $env:OLLAMA_HOST`
- PowerShell を再起動

### Tailscale 経由で繋がらない

- 自宅 PC の Tailscale が「running」か
- Windows ファイアウォールでポート 11434 開放
- `OLLAMA_HOST=0.0.0.0:11434` で `0.0.0.0` （`localhost` だと外部不可）

### Flutter Windows ビルドエラー

**「Unable to find suitable Visual Studio toolchain」**
→ Visual Studio Community 2022 + 「C++によるデスクトップ開発」インストール

**「Building with plugins requires symlink support」**
→ 開発者モード ON（`start ms-settings:developers`）

**audioplayers の C2338 / C4819 エラー**
→ `windows/CMakeLists.txt` の `APPLY_STANDARD_SETTINGS` に `/utf-8` と `_SILENCE_EXPERIMENTAL_COROUTINE_DEPRECATION_WARNINGS` 追加

### Unity の WebSocket 接続失敗

- Flutter 側が起動してて WebSocketサーバーがリスニング中か
- ポート 8765 が他で使われてないか
- Unity Console のエラー確認

### Unity のシーン変更が消える

- Ctrl+S でシーン保存忘れずに
- Play モード中の変更は保存されない
- Unity 標準 `CharacterController` との名前衝突注意（自作は `RAiMCharacterController`）

### VOICEVOX で音が出ない

- タスクトレイで VOICEVOX が起動してるか
- `http://localhost:50021/docs` でAPI画面が出るか
- Windows サウンドミキサーで音量確認

### LLM の応答が変

- temperature を 0.3 程度に下げる
- システムプロンプトを見直す
- format: 'json' を指定してるか確認
- 会話履歴が長すぎる場合: 直近10件くらいに絞る
