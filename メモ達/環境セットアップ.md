# RAiM 環境セットアップガイド

## このドキュメントについて

新しく RAiM プロジェクトに参加するメンバーが、ゼロから開発環境を構築して `flutter run` できるまでの手順をまとめたもの。

**所要時間**: 全てゼロから始めて約 3〜5 時間(各種 DL 時間含む)

**前提**: Windows PC、Git の基本操作はわかる

合わせて読むドキュメント:
- `まとめ.md` — プロジェクト全体設計
- `実装まとめ.md` — コード設計と現在の到達点
- `フォルダ構成.md` — Flutter 構造
- `Dartガイド.md` — Dart 文法
- `Git運用ルール.md` — Git 操作のお作法
- `TTS比較.md` — TTS 技術選定の記録

---

## ⚠️ 最重要: 日本語パス禁止

**Android Tools (Java/Gradle) は日本語パスを含むディレクトリで動作しない。**

```
❌ NG: H:\開発\RAiM_prot\Flutter_Test\...
✅ OK: H:\dev\RAiM_prot\Flutter_Test\...
```

エラーメッセージ例:
> Project path contains non-ASCII characters at position 3, Android Tools don't work properly with non-ASCII paths.

プロジェクトを置く場所を必ず**英数字のみのパス**にすること。具体的には以下のフォルダ全てを ASCII 名にする:

- `H:\開発\` → `H:\dev\` のように変更
- ユーザー名が日本語の場合は要注意(Windows のユーザーフォルダ名)

## セットアップ手順

### Phase 1: 基礎ツール(順序自由)

#### 1. Git

1. https://git-scm.com/download/win から DL してインストール
2. 設定:
   ```powershell
   git config --global user.name "Your Name"
   git config --global user.email "your@email.com"
   ```

#### 2. Visual Studio Code

1. https://code.visualstudio.com/ から DL
2. 推奨拡張機能:
   - **Flutter** (Dart-Code.flutter)
   - **Dart** (Dart-Code.dart-code)
   - **GitLens** (eamodio.gitlens)
   - **Material Icon Theme** (PKief.material-icon-theme)

#### 3. Visual Studio Community 2022

Flutter Windows ビルドに必須。

1. https://visualstudio.microsoft.com/ja/downloads/ から DL
2. インストール時に **「C++ によるデスクトップ開発」** ワークロードを選択
3. (他のワークロードはチェック不要)

#### 4. Android Studio

1. https://developer.android.com/studio から DL してインストール
2. 初回起動時に「Standard」セットアップを選択(全部入りで自動セットアップされる)
3. インストール完了後、`File > Settings > Languages & Frameworks > Android SDK`:
   - `SDK Platforms` タブ: **Android 14 (API 34)** または **Android 15 (API 35)** を選択
   - `SDK Tools` タブ: **Android SDK Command-line Tools (latest)** にチェック → Apply

#### 5. Flutter SDK

1. https://flutter.dev/docs/get-started/install/windows から DL
2. **`H:\flutter\` のような ASCII パスに展開**(`C:\Program Files\` だと権限問題で詰むことが多い)
3. 環境変数 `Path` に `H:\flutter\bin` を追加
4. PowerShell を**再起動**してから確認:
   ```powershell
   flutter --version
   ```

#### 6. Android ライセンス承諾

```powershell
flutter doctor --android-licenses
```

`y` を 10回くらい連打して承諾。

#### 7. Flutter Doctor 確認

```powershell
flutter doctor
```

全て `✓` になれば OK。`!` や `X` があれば指示に従って対応。

主な確認項目:
- ✓ Flutter
- ✓ Windows Version
- ✓ Android toolchain
- ✓ Chrome
- ✓ Visual Studio
- ✓ Android Studio
- ✓ VS Code

### Phase 2: Unity 環境

#### 1. Unity Hub

1. https://unity.com/download から Unity Hub DL
2. インストール、Unity ID でログイン(Personal ライセンスで OK)

#### 2. Unity Editor 2022.3.22f1

**バージョン厳守**。班員と Unity バージョンが揃ってないとプロジェクトが壊れる。

1. Unity Hub → Installs → Install Editor
2. 「Archive」リンクから 2022.3.22f1 を選択
3. インストール時のモジュール:
   - ☑ **Android Build Support** (IL2CPP, NDK, SDK 自動入れてくれる)
   - ☑ **iOS Build Support**(Mac は別途必要だが、Win でも入れとく)
   - ☑ **Windows Build Support (IL2CPP)**
   - (日本語パックは任意)

#### 3. Unity Hub の Android SDK パス確認

Unity Hub の Android Build Support で勝手に SDK が入る場合と、Android Studio の SDK を参照する場合がある。**両方混在すると事故るので統一**:

Unity Editor で:
- `Edit > Preferences > External Tools`
- Android SDK Tools: Android Studio が使ってる SDK パスに合わせる
  - 通常: `C:\Users\<ユーザー名>\AppData\Local\Android\Sdk`
- JDK: Unity 内蔵 JDK で OK
- Android NDK: Unity 内蔵 NDK で OK

### Phase 3: ローカル LLM 環境(不要)

#### 1. Ollama

1. https://ollama.com から Windows 版 DL & インストール
2. **環境変数を追加**:
   - `OLLAMA_HOST` = `0.0.0.0:11434`
   - 設定方法: Windows の「環境変数の編集」→ ユーザー環境変数に追加
3. **Windows ファイアウォール**: ポート 11434 (TCP) の受信を許可
   - スタートメニュー → 「Windows Defender ファイアウォール」→ 詳細設定 → 受信の規則 → 新規作成
4. モデル DL:
   ```powershell
   ollama pull gemma3:12b
   ```
   約 8GB ダウンロード、回線次第で 5〜30 分

#### 2. VOICEVOX

1. https://voicevox.hiroshiba.jp/ から DL
2. インストール
3. 起動するとタスクトレイに常駐、`localhost:50021` で HTTP サーバーが立つ

#### 3. Tailscale(自宅 PC ↔ 学校 PC を VPN 接続)(不要)

学校から自宅 Ollama を叩く用。

1. https://tailscale.com でアカウント作成(Google/GitHub アカウントで OK)
2. 自宅デスクトップにインストール、ログイン
3. **「Run unattended」設定**(再起動後も自動接続)
4. Tailscale IP(`100.x.x.x` 形式)をメモ
5. 学校ノート PC にも**同じアカウント**でインストール
6. 確認:
   ```powershell
   # 学校 PC から自宅 Ollama に ping
   ping 100.x.x.x   # 自宅 PC の Tailscale IP
   curl http://100.x.x.x:11434/api/tags
   ```

### Phase 4: プロジェクト取得

#### 1. リポジトリ clone

**日本語パスに注意**。`H:\dev\` のような ASCII パス内に置く:

```powershell
cd H:\dev
mkdir RAiM_prot
cd RAiM_prot
git clone https://github.com/Andodazo/Flutter_Test.git
cd Flutter_Test\raim_prototype
```

#### 2. Flutter 依存パッケージ取得

```powershell
flutter pub get
```

#### 3. Unity プロジェクトを Unity Hub に登録

1. Unity Hub → Projects → 「Add」ボタン
2. `H:\dev\RAiM_prot\Flutter_Test\raim_prototype\unity\raim_unity\` を選択
3. Editor バージョンに `2022.3.22f1` を指定して開く

初回起動は時間がかかる(`Library/` フォルダの再生成、数分)。

#### 4. Windows で動作確認

Ollama / VOICEVOX 起動状態で:

```powershell
cd H:\dev\RAiM_prot\Flutter_Test\raim_prototype
flutter run -d windows
```

Unity Editor 側でも `unity/raim_unity` を開いて Play モードにする(WebSocket クライアントとして接続される)。

「おはよう」と入力して、ライムの応答が返ってきて音声が流れたら成功。

### Phase 5: Android ビルド準備

#### 1. Unity Export (Android)

Unity Editor で:

```
Window > Flutter Embed Unity > Export Android
```

**通常の Build Settings → Build じゃなく、このメニューを使う**。flutter_embed_unity 専用の Export 処理が走り、Flutter プロジェクトの `android/unityLibrary/` に直接出力される。
無ければ自分で作成

初回 Export は時間がかかる(IL2CPP コンパイル、10〜20 分)。

#### 2. `android/unityLibrary/` の Git 扱い

**絶対に Git に commit しない**。理由:

- 自動生成物(数千ファイル、数GB級)
- 各自の Unity バージョン・SDK バージョンに依存
- リポジトリが肥大化する

`.gitignore` に以下が含まれているか確認:

```gitignore
android/unityLibrary/
android/.gradle/
ios/UnityFramework/
ios/UnityLibrary/
```

詳細は `Git運用ルール.md` 参照。

#### 3. Android 実機ビルド

USB デバッグを有効化した Android 端末を USB 接続して:

```powershell
flutter devices   # 端末が認識されているか確認
flutter run -d <端末ID>
```

初回ビルドは長い(10〜30 分)。

### Phase 6: iOS ビルド準備(Mac 環境)

**iOS ビルドには Mac が必須**。Apple Developer 無料登録(個人開発者証明書)で実機転送可能。

(詳細は Mac を借りた後に追記予定)

主な手順イメージ:
1. Mac で Xcode インストール
2. Flutter / Unity を Mac に同様にセットアップ
3. `git clone` で同じプロジェクト取得
4. `cd ios && pod install`
5. Unity Editor で `Window > Flutter Embed Unity > Export iOS`
6. Xcode で署名設定(個人 Apple ID)
7. `flutter run -d <iPhone>`

## よくあるトラブルと解決法

### 「Project path contains non-ASCII characters」

**原因**: パスに日本語が含まれている
**解決**: プロジェクトを ASCII パス(`H:\dev\` 等)に移動

### 「Unable to find suitable Visual Studio toolchain」

**原因**: Visual Studio Community 2022 がない、または C++ ワークロード未インストール
**解決**: VS Community 2022 + 「C++ によるデスクトップ開発」を入れる

### 「Building with plugins requires symlink support」

**原因**: Windows 開発者モード OFF
**解決**: PowerShell で `start ms-settings:developers` → 開発者モード ON

### audioplayers の C2338 / C4819 エラー(Windows ビルド時)

**原因**: VOICEVOX 用 audioplayers パッケージの C++ コンパイル互換性
**解決**: `windows/CMakeLists.txt` の `APPLY_STANDARD_SETTINGS` 関数に以下を追加:

```cmake
target_compile_options(${TARGET} PRIVATE "/utf-8")
target_compile_definitions(${TARGET} PRIVATE _SILENCE_EXPERIMENTAL_COROUTINE_DEPRECATION_WARNINGS)
```

### Ollama に繋がらない

確認順:
1. タスクトレイにラマアイコンがあるか
2. 環境変数 `OLLAMA_HOST` が `0.0.0.0:11434` か
3. PowerShell で `echo $env:OLLAMA_HOST` で反映確認
4. PowerShell **再起動**(環境変数反映のため)
5. ファイアウォール 11434 開放確認

### Tailscale 経由で繋がらない

確認順:
1. 自宅 PC の Tailscale が「running」状態か
2. `OLLAMA_HOST` が `0.0.0.0:11434`(`localhost` だと外部不可)
3. Windows ファイアウォールで 11434 受信許可
4. 学校 Wi-Fi で Tailscale が通るか
   - 学校によっては VPN 通信ブロックされる可能性、通った時は記録しておく

### Unity の WebSocket 接続失敗

確認順:
1. Flutter 側が起動して WebSocket サーバーが立っているか
2. ポート 8765 が他で使われていないか(`netstat -an | findstr 8765`)
3. Unity Console のエラー確認

### Unity Editor でシーン変更が消える

**原因**: Ctrl+S での保存忘れ、または Play モード中の変更
**解決**:
- 編集後は必ず Ctrl+S
- Play モード中の変更は保存されない(Unity の仕様)
- Unity 標準 `CharacterController` との名前衝突注意(自作は `RAiMCharacterController`)

### VOICEVOX で音が出ない(不要)

確認順:
1. タスクトレイで VOICEVOX が起動しているか
2. `http://localhost:50021/docs` でブラウザから API 画面が出るか
3. Windows サウンドミキサーで該当アプリの音量

### LLM の応答が変、JSON 崩れる

確認順:
1. `temperature` を 0.3 程度に下げる(`OllamaService.sendMessage` 内)
2. システムプロンプトを見直す
3. `format: 'json'` を指定しているか
4. 会話履歴が長すぎる場合、直近 10 件程度に絞る

### Android Studio が起動しない / 重い

メモリ不足の可能性。設定で:
- `Help > Edit Custom VM Options` で `-Xmx2048m` 程度に制限
- 不要なプラグインを無効化

### `flutter run -d windows` で起動しない

確認順:
1. Visual Studio Community 2022 + C++ ワークロード入っているか
2. Windows SDK が入っているか(VS インストーラ確認)
3. `flutter clean` 後に `flutter pub get` → 再ビルド
