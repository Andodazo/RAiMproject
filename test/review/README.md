# クライアントのレビュー課題

セキュリティレビューで見つかった、クライアント側の問題です。
1つずつ直して、確認用のテストが通れば完了です。

## 進め方

1. main から自分のブランチを切る
2. 課題を1つ選んで直す
3. 確認用のテストを動かす（下の「テストの動かし方」）
4. 通ったら次の課題へ。全部通ったら PR を出す

直し方は自由です。ただし、テストが呼ぶ名前（下の「決まっている名前」）は、そのとおりに作ってください。

## テストの動かし方

プロジェクトの直下（`pubspec.yaml` がある所）で:

```powershell
dart run tools/review_check.dart 3        # 課題3だけ
dart run tools/review_check.dart 1 4 6    # いくつか
dart run tools/review_check.dart all      # 全部
```

1つずつ `flutter test` で動かしても同じです。

```powershell
flutter test test/review/item3_older_history_test.dart
```

最後に「OK」か「だめ」が課題ごとに出ます。日本語が文字化けするときは、先に `chcp 65001` を実行してください。

取りかかる前の課題は、テストが落ちるのが正しい状態です。名前がまだ無ければ、コンパイルエラーで落ちます。

## 決まっている名前

テストが呼ぶので、この名前と形で作ってください。

| 課題 | 名前 | 中身 |
|---|---|---|
| 準備（1・3・4・6） | `ChatProvider(..., audioQueue: AudioPlayQueue?)` | 音声キューを外から渡せるようにする。省略したら今までどおり自分で作る |
| 1 | `ChatProvider.resetForSignOut()` | ログアウトしたときに呼ぶ |
| 4 | `UnityCommunicator.sendError({required String message})` | Unity（Windows の吹き出し）に失敗を知らせる |
| 5 | `RaimConfig.isAwsUrl(String url)` | トークンを付ける相手なら true |
| 5 | `RaimConfig.enableServerSwitch` | 接続先の切り替えを出すか |
| 6 | `RaimConfig.maxImageCount` | 1回に送れる画像の枚数 |

`audioQueue` は、テストで音を鳴らさないためのものです。本物の `AudioPlayQueue` は、作っただけで音のプラグインを呼ぶので、テストの中では作れません。

## 課題1: ログアウトしても前の人の会話が残る

**起きていること**: Windows でログアウトしてから別の人がログインすると、前の人の会話・会話 ID・会話一覧・選んだまま送っていない画像が、そのまま残っています。スマホで、ログアウトしたあとにアプリを終了できなかったとき（iOS など）も同じです。

**どうなればいいか**
- ログアウトしたら、前の人の会話・会話 ID・一覧・読み込み中の表示・選んだ画像が消える
- ログアウトの前に読み始めた一覧が、ログアウトの後に届いても（失敗しても）、次の人の画面に出ない

**ヒント**: `ChatProvider` と `CameraProvider` は、どこで作られているでしょうか。ログイン画面より上で作られているなら、ログアウトしても消えません。

## 課題2: トークンの更新中にログアウトすると、前の人のトークンが戻る

**起きていること**: アクセストークンの更新（Cognito への通信）を待っている間にログアウトすると、更新の返事が届いたときに、前の人のトークンを保存し直してしまいます。ログアウトしたのに、ログインしたままになります。

**どうなればいいか**
- 更新の返事がログアウトの後に届いても、保存しない・返さない
- ログアウトが Cognito の revoke を待っている間に更新が始まっても、トークンが戻らない
- 前の人の更新が後から断られても、次にログインした人のトークンを消さない

**ヒント**: 「この更新は、いつのログインのものか」を覚えておく方法を考えてみてください。

## 課題3: 古いメッセージの読み込み中に会話を切り替えると、前の会話が混ざる

**起きていること**: 上にスクロールして古いメッセージを読み込んでいる間に別の会話へ切り替えると、読み込みが終わったときに、前の会話の古いメッセージが今の会話の先頭に入ります。

**どうなればいいか**
- 読み込みが終わったときに会話が変わっていたら、その結果は使わない
- 切り替えなければ、今までどおり先頭に入る

## 課題4: 返事の途中でエラーになると、途中の文が残る

**起きていること**: サーバーは返事を速く見せるため、最後の確認より先に本文を流しています。そのあとエラーになると、途中まで流れた文が正しい返事のように残り、声も鳴り続けます。

**どうなればいいか**
- 途中の文を消して、エラーの知らせだけを残す。吹き出しが分かれていたら（`bubble_break`）、前の吹き出しも消す
- 声を止める
- Windows では、Unity の吹き出しも失敗の知らせに変える（Unity 側で `type: "error"` を受け取って出す）
- 前の返事や、送った発言は消さない

**ヒント**: `_currentStreamingMessage` は、いちばん最後の吹き出ししか指していません。

## 課題5: 配布版でも接続先の切り替えが出る・トークンを付ける相手の決め方が甘い

**起きていること**
- 配布用に `RAIM_ENABLE_SERVER_SWITCH=false` を付けても、スマホと Windows のメニューに、開発用サーバーへの切り替えが出ます
- AWS かどうか（トークンを付けるか）を、URL に `cloudfront.net` が含まれるかで決めています。`wss://cloudfront.net.example.com` のような別のサーバーにもトークンを送ってしまいます

**どうなればいいか**
- フラグが false ならメニューに出さない。`switchServer` もフラグを見て止める
- フラグを付けずに release ビルドしたときも出さない（`tools/release.ps1` を通さずに `flutter build apk` で作った場合など）
- トークンを付けるかは、URL のホスト名で決める

## 課題6: 画像を5枚以上選べるが、サーバーは4枚まで

**起きていること**: アプリでは10枚まで選べますが、サーバー（Edge Lambda）は4枚までです。5枚以上だと、アップロードしたあとでサーバーに断られます。

**どうなればいいか**
- 上限を1か所（`RaimConfig.maxImageCount`）にまとめて、4枚にする
- 5枚目からは選べない。超えた分は入れなかったと知らせる
- 送るときも、超えていたらアップロードする前に止めて、何枚までかを知らせる

## 課題7: Unity が会話の中身をログに出している

**起きていること**: Unity が Flutter や WebSocket から受け取ったメッセージを、JSON ごと `Debug.Log` に出しています。会話の内容がログファイルに残ります。

**どうなればいいか**
- 受け取ったものの中身は出さず、種類（`type`）や長さだけを出す

## 課題8: 鍵が無くても release ビルドができてしまう

**起きていること**: `android/key.properties` が無い PC で release ビルドすると、黙って debug の鍵で署名されます。その版を配ると、鍵が違うので上書きインストールできません。

**どうなればいいか**
- 鍵が無いときは、release を作ろうとしたところでビルドを止めて、理由を出す
- debug のビルドは今までどおり鍵が無くてもできる

## 課題9: 使っていない機能が残っている

**起きていること**: もう使わない展示モード（Flutter・Unity・Windows の起動引数）と、駅アラームの録音機能（確認用）が残っています。

**どうなればいいか**
- 展示モードのコードを全部消す（`DemoAccountPolicy` とそのテストも）
- 録音機能のコードを全部消す（Android の書き出し、iOS の Info.plist で「ファイル」アプリに見せる設定も）
